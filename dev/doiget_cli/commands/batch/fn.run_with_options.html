Run the doiget batch <path> subcommand.

When dry_run is true (per ADR-0022 §1 + §3): read the input file, parse refs, and emit one FetchPlan JSON envelope line per ref on stdout. NO provenance log is opened, NO HTTP client is built, NO per-ref fetch runs, NO store write happens. Per-ref parse failures in dry-run mode are still counted and the function returns Err(...) if any ref failed to parse — the input was malformed and the caller should know.

When dry_run is false, runs the normal multi-ref orchestration — see the module-level docs for the failure-semantics contract.

Slice 5 (PR #84 advisory item A2/A3 refactor): the previous BatchOptions { dry_run: bool } single-field option bundle plus the thin run(path) backwards-compat wrapper were collapsed into this single dry_run: bool parameter — the option bundle’s single-bool shape was YAGNI, and the wrapper only existed to spare integration tests a BatchOptions::default() literal.
